01 / Build From source to checked JAR

GitHub Actions · Gradle

Build first.
Inspect the package.

The repository’s Build workflow runs on pushes to main and arena/**, pull requests, and manual dispatch. It prepares Temurin JDK 25 and Gradle, then runs the project’s Gradle wrapper to build the mod.

  1. Compile the project. The workflow runs ./gradlew build --stacktrace after setting the wrapper executable.
  2. Check the JAR’s structure. It verifies fabric.mod.json, the mixin configuration, and compiled mod classes are present.
  3. Check packaged entity textures. The workflow checks for the expected Herobrine and Steve-friend texture files, then uploads the mod JAR as a workflow artifact.

02 / Release Versioned releases

A second set of checks

A release tag has to match.

The release workflow accepts version tags or a manual run with a tag. It compares the tag with mod_version, rebuilds the project, checks the JAR version and required files, and only then creates the GitHub release and uploads its artifact.

Safety / scope, not a guarantee

“Non-destructive” has limits.

The project README describes the mod as non-destructive by design: it avoids player-built structures, with optional fire called out as an exception. Its intended haunting events can still alter the world environment. Back up worlds before installing or updating any mod, and use builds from a source you trust.

The workflow above checks that a build completes and that expected files are packaged. It is not a full code-security review and cannot prove every runtime behavior is risk-free.

From The Fog stays opt-in. Its tick/load functions are not registered with Minecraft’s automatic function tags; the bundled content is off by default and must be enabled from Herobrine’s settings or its documented command.
WAKE_UP.vbs is not an installer. The upstream source note says it displays message boxes and opens a website. It is optional and not required to play the mod or datapack; run it only if you intend that behavior.
